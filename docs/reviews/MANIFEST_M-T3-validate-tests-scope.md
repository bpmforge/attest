# MANIFEST — M-T3-validate-tests-scope (WP-T3)

Branch `feat/test-impact-validate` (from main @ 2f9b0b8). Spec: `docs/work/TEST_IMPACT_PLAN.md` §2.3-2.4, §3, §5 T3. Not pushed.

## What changed

- `validate-tests.sh [root] [--scope auto|impact|full]` (default `auto`, env `TEST_SCOPE`; bad value = exit 2). Flow: `map.mjs refresh` -> `select.mjs --json` -> `Scope:` line (stderr + top of `RUNTIME_tests_<date>.md`) -> run -> ledger.
  - `impact` and `auto` take the same decision (impact unless the selector says full: safety rules always win, so a lockfile change never rides an impact run). `full` = the project's own command (unchanged path). A custom `"test"` string in `.sdlc/sdlc.json` forces full (it cannot be narrowed to files); no `select.mjs` / no node -> full.
  - Impact execution is a node executor embedded in the script (write scope allows no new file): per `by_runner` entry and project — vitest `run --reporter=json --outputFile=<tmp> <files>`, jest `--json --outputFile --runTestsByPath <files>`, playwright `test <files>` (same reporter-flag rule as before; `PLAYWRIGHT_JSON_OUTPUT_NAME`, `PLAYWRIGHT_HTML_OPEN=never`), node `--test <files>`, pytest `<files> -rA --color=no` (plus `--testmon -rA` when args are `--testmon`), go `go test -json <./pkg args>`, cargo `cargo test -p <crate>` once per crate. Binary resolution: `node_modules/.bin` up to the root, then PATH; a missing runner -> gap `no-test-command` (exit-3 path).
  - Contract kept: stdout is the validator JSON envelope; `RUNTIME_tests_<date>.md` same verdict text (`PASS|FAIL — N passed, M failed`), the Scope line is added to the body; `test-results.json` is still written (merged vitest/jest shape of what ran, else the Playwright JSON) — after an impact run it lists only the files that ran (P0 UC tests are in the always-set, so UC verdicts stay present).
  - Per-file harvest (ledger rows): vitest/jest JSON `testResults[].status`; Playwright JSON specs per file (unexpected = fail, flaky = pass + `flaky`); pytest `-rA` PASSED/FAILED/ERROR/SKIPPED lines per file; go `-json` package result mapped (module path stripped) to each selected test file in that package dir; cargo per crate (rc of the crate's run) to the crate's test files; node `--test` and anything the parser did not see: the invocation's overall result. Counts: `TOTAL: P passed, F failed` is appended to the log from JSON/go/cargo counts (the pre-existing `N passed` greps pick it up).
  - Ledger: every run calls `ledger.mjs record` (impact: chain +1; full: green = baseline `{sha,date}` + chain 0, red = per-file only). Full runs by the project's own command harvest per file from a fresh `test-results.json` when the run wrote one, else the overall result for every test file in the map. Red selected test: gap `tests-failed`, ledger rows recorded, no re-run; the failed file is re-selected next time by the selector's failed set.
- `run-handoff-gates.sh --runtime` now also runs `validate-tests.sh --scope <S>` (new flag `--test-scope`, default `impact`; `--scope` there is already the git-writes dir). `validate-phase-gate.sh <phase> [root] [--test-scope]` passes `--scope` to validate-tests only (no flag = validator default); phase-5 is always `--scope full`. `run-coverage-loop.sh <phase> [root] [--test-scope]`: iteration 1 passes only what was asked (default: phase gate default = auto), iterations 2-3 default to `impact`.
- `conductor.mjs`: `--test-scope impact|auto|full` (default impact; invalid = exit 2) -> Round 3 `validate-tests.sh <wt> --scope <value>` (the RUNTIME doc table shows the exact command). `integration-review.mjs`: after the three existing validators it runs `validate-tests.sh <root> --scope full` (informational like the others; row `validate-tests.sh --scope full` in the validator table, logged in `integration.validators` with `tests_cmd`; 60 min timeout for that one).
- `validate-release-readiness.sh` check 14: if the project has a test runner manifest, the ledger's `full.sha` must equal HEAD. Gaps: `no-full-test-run`, `full-test-run-stale` (names both shas, commits behind, the fix command), `full-test-run-not-ancestor`, `full-test-run-unverifiable` (no git). No manifest -> skipped with a note. The release gate itself does not run tests; the phase-5 gate does (forced full) before it.
- Docs: `scripts/validators/README.md` (new "Test scope" section), `scripts/conductor/README.md` (flag row), `docs/UNATTENDED_EXECUTION.md` (Test scope paragraph incl. the release rule).

## Decisions / things reviewers should look at

- Bug fixed on the way: `_lib.sh` runs under `set -e`, so a failing `npm test`/playwright run aborted `validate-tests.sh` before the gap, the RUNTIME report and the JSON envelope (exit 1 with nothing on stdout; reproduced on the old script). The two run sites now wrap the command in `set +e/-e`, which the ledger recording for red runs needs.
- Playwright config present + other runners in the map: the old fast path ran only Playwright, so a "full" run did not cover unit tests and could not honestly become a baseline. On a full run a green Playwright half is now followed by the project's test command when the map holds non-Playwright tests (report written by the second half). Behavior change for such projects: their gate now also runs `npm test`. Revert by making `OTHER_RUNNERS` always `no` if undesired.
- `impact` == `auto` by design; the difference is only the caller's tier label. If a stricter `impact` (never auto-widen) is wanted, safety rules would have to be bypassed, which the plan's §3 forbids.
- Release rule is strict equality with HEAD (a docs-only commit after the full run makes the ledger stale); ledger `tree` is not checked because the run's own RUNTIME report dirties the tree.
- An empty impact selection runs nothing, passes, and still records a run (chain +1).
- Not exercised by an automated test: jest, playwright, node, pytest, go, cargo harvesting in the executor (smoke-run by hand on scratch go / cargo workspace / pytest fixtures: per-file rows, selection, red go package, `TOTAL:` line OK; jest/playwright/node follow the same code path as the vitest stub); `run-handoff-gates.sh --runtime` end to end (needs a valid manifest; checked by `bash -n`, `--help`, and the bad `--test-scope` exit 2).
