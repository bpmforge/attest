**Repo:** `/Users/user/Code/bpm-opencode-experts/` (v0.16.0)
**Auditor:** Claude (Opus 4.7, 1M ctx)
**Trigger:** User reported (a) ASCII charts in SDLC-generated docs from another machine, (b) onboarding not looping reliably (Ralph Wiggum sometimes skipped), (c) gates only check doc approval — need gates that actually run/verify, (d) prompts too large in a single instance, (e) no functionality should be lost.

## Executive summary

The project's bones are good. The v0.15 refactor genuinely made `sdlc-lead.md` a router (497 lines, down from 4986), and the validators in `scripts/validators/` perform real structural completeness checks (route enumeration from source, table enumeration from source, P0 use-case → sequence-diagram coverage). Specialist coverage (code-reviewer, security-auditor, test-engineer, performance-engineer, ux-engineer) is intact across all four modes.

But six structural issues degrade reliability:

| # | Severity | Issue |
|---|----------|-------|
| 1 | HIGH | ASCII box-drawing banners in 4 SDLC mode files leak into deliverables (confirmed in `docs/USERGUIDE.md` already) |
| 2 | MEDIUM | Ralph Wiggum loop is opt-in (`--deep`) — default modes don't iterate to coverage |
| 3 | CRITICAL | Phase gates check doc existence + grep "PASS"; nothing actually runs the build, tests, or smoke |
| 4 | HIGH | Mode files still monolithic (sdlc-init-mode 1868 lines, security-auditor 2227 lines) — exceeds local-LLM effective context |
| 5 | LOW–MEDIUM | Code-review/strict coverage is wired in, but agent self-report isn't verified |
| 6 | HIGH | Completeness validators exist but are partial; no universal "loop until clean" pattern outside `--deep` |

## Finding 1 — ASCII-chart leakage [HIGH] — confirmed

**Mechanism:** SDLC mode files use `═══...═══` Unicode box-drawing as banner separators around HANDOFF blocks.

| File | Box-drawing line count |
|------|------------------------|
| `agents/sdlc-init-mode.md` | 88 |
| `agents/sdlc-improve-mode.md` | 36 |
| `agents/sdlc-onboard-mode.md` | 27 |
| `agents/sdlc-feature-mode.md` | 22 |
| `agents/shared/SCOPE_BOUNDARY.md` | 3 |
| **Total in agent prompts** | **176** |

Verified scope:
- `agents/shared/HANDOFF_TEMPLATES.md` — clean (0 banners). Canonical template is fine.
- **Direct evidence of leakage:** `docs/USERGUIDE.md:143–151` already has the banners in this repo's own user-facing documentation.
- Scripts (`install-mempalace.sh`, `cache-registry-packs.sh`, `semgrep-full-audit.sh`) use them for terminal-output formatting — those are fine.

Specialist agents (db-architect, code-reviewer, etc.) all carry the rule "ALL diagrams MUST use Mermaid syntax — NEVER ASCII art." But the four SDLC mode files lack this rule and ACTIVELY MODEL the opposite. `sdlc-improve-mode.md:896` even states the rule while violating it 36 times.

`scripts/validators/validate-architecture.sh` is well-built — it enforces real Mermaid fences with first-line keyword validation in `ARCHITECTURE.md`. But no equivalent backstop exists for `VISION.md`, `HEALTH_ASSESSMENT.md`, `USE_CASES.md`, `ONBOARDING.md`, or any other deliverable.

Local LLMs (Qwen3-coder, Gemma-3-27b) reliably imitate in-prompt visual style. Unguarded deliverables get the banner style copied into them.

## Finding 2 — Ralph Wiggum opt-in only [MEDIUM]

`agents/sdlc-onboard-mode.md:651` runs Ralph only when user adds `--deep`. Default `/sdlc onboard` is `--quick` and never enters the inventory loop. Mode 1 (init) and Mode 4 (improve) don't use Ralph at all.

The Ralph loop itself is well-designed:
- INVENTORY → DISCOVER → VERIFY → GAP → REPEAT (3-iteration cap)
- Escalates with explicit waiver/lower-bar/escalate/manual options
- Validators give objective coverage % rather than confidence feel

Problem: an unprompted user runs `/sdlc onboard` and gets the 7-step pass without coverage iteration. There's no scaling — minimal Ralph for default, exhaustive Ralph for `--deep`.

## Finding 3 — Gates are performative, not operational [CRITICAL]

Validators check filesystem state, not system state.

| Phase | What gate checks | What it does NOT check |
|-------|------------------|------------------------|
| phase-0 | VISION.md, COMPETITIVE_ANALYSIS.md exist | content quality |
| phase-1 | 4 doc files exist | content quality |
| phase-2 | 3 doc files exist | content quality |
| phase-3 | doc structure: arch, api-coverage, sequence-coverage, erd-coverage | doc consistency, that schema actually compiles, that openapi.yaml validates |
| **phase-4** | **NOTHING** ("per-module RUNTIME — handled inline") | build, lint, typecheck, tests, server boots |
| phase-5 | greps for "PASS" / "APPROVED" / "READY" in `RUNTIME_*.md` / review files | actual test execution, actual build, actual server boot, actual smoke |
| onboard-deep | inventory rows have artifacts | artifacts are accurate |
| security-deep | OWASP categories present, attack-chains.md exists | findings actually reproduced, fixes verified |

**No validator runs:**
- `npm run build` / equivalent
- `npm run lint` or typecheck
- `npm test` / `pytest` / `cargo test`
- Server-boot smoke (start server, hit known route, assert 200)
- Dependency CVE scan (`npm audit`, `osv-scanner`)
- Migration apply test
- OpenAPI spec validation (`redocly lint`, `swagger-cli validate`)
- ERD ↔ schema-file consistency

The phase-5 release gate trusts agent self-report. An agent writes "verdict: PASS" in markdown; the validator greps for the literal "PASS" → exit 0. Nothing was actually executed.

## Finding 4 — Prompt-size bloat [HIGH]

| File | Lines | Est. tokens |
|------|-------|-------------|
| `security-auditor.md` | 2227 | ~89K |
| `sdlc-init-mode.md` | 1868 | ~75K |
| `performance-engineer.md` | 1327 | ~53K |
| `sdlc-improve-mode.md` | 908 | ~36K |
| `sdlc-onboard-mode.md` | 841 | ~34K |

The v0.15 split moved Mode-N content out of `sdlc-lead.md` (down from 4986 → 497 lines) but the mode files themselves are still monolithic. When sdlc-lead routes to Mode 1, the model loads `sdlc-lead.md` (497) + `sdlc-init-mode.md` (1868) + at least one shared protocol = ~2400 lines / ~96K tokens before any work.

For local LLMs with effective 32K–128K context, that's near or above the limit. Even at 1M context (Opus), attention degradation past ~50K is documented. The user's "prompts too large, getting lost" intuition matches the data.

## Finding 6 — Completeness gaps [HIGH]

Existing completeness validators (these DO enumerate from source and verify every X has an artifact):

| Validator | Source enumeration |
|-----------|--------------------|
| `validate-api-coverage.sh` | Express/Fastify/Next.js/FastAPI/Flask/Go routes |
| `validate-erd-coverage.sh` | Prisma/TypeORM/Knex/SQLAlchemy/Django/raw SQL tables |
| `validate-sequence-coverage.sh` | P0 use cases in USE_CASES.md |
| `validate-inventory.sh` | INVENTORY.md rows (5 categories) |
| `validate-architecture.sh` | All 6 diagram types, real Mermaid fences |
| `validate-owasp.sh` | All 10 OWASP categories ≥ confidence 7 |

Real work, not stub. But several gaps remain:

**Missing validators:**
- `validate-c3-coverage.sh` — every `src/` subdir has a C3 component entry
- `validate-entry-points.sh` — every server bootstrap, CLI entry, worker, cron is documented
- `validate-use-cases.sh` — every entry point has a use case; every user story has acceptance criteria
- `validate-tech-stack.sh` — every package.json/Cargo.toml/go.mod/requirements.txt dependency in TECH_STACK.md
- `validate-tests-mapping.sh` — every P0/P1 use case has a test; every test maps to a use case
- `validate-fix-backlog-closed.sh` — every CRITICAL/HIGH finding has a verified fix before phase-5
- `validate-adrs.sh` — every "decision" in DECISION_LOG/ARCHITECTURE has an ADR file with status
- `validate-migrations.sh` — every DB migration has a corresponding schema/ERD update

**Universal loop missing.** Validators report gaps once; nothing forces re-iteration outside `--deep`. The Ralph 3-iteration cap should apply to every mode, not just deep mode.

**Tracker doesn't gate.** `SDLC_TRACKER.md` rows go PENDING→DONE on agent self-report. No script verifies "DONE" matches reality.

**No reverse coverage on tests.** TEST_PLAN.md is text. Nothing asserts every test file in `tests/` corresponds to a documented use case, or vice versa.

## What we're explicitly NOT changing

- `sdlc-lead.md` routing logic (497 lines, working)
- The `task()` vs HANDOFF tier system (good)
- The `BOUNDED_TASK_CONTRACT.md` / `HANDOFF_TEMPLATES.md` shared files (clean)
- Specialist agent counts or roles (no expert is being removed)
- Existing validators that work (api-coverage, erd-coverage, sequence-coverage, inventory, architecture, owasp)
- Confidence-based gates for narrative artifacts (VISION, summaries) — those are inherently subjective and the 1-10 loop is appropriate

The goal is to add what's missing, not to refactor what works.
