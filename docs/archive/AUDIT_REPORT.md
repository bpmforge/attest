# The Great Instruction Audit (T13.1)

**Status:** Report-only. No files were edited as part of this audit — per the ticket contract, this document classifies every instruction block found across `agents/**` and `skills/**` and surfaces contradictions, stale calibration, and weaker-model scaffolding. Fixes are out of scope here; they belong to the follow-up tickets named throughout (T13.2 core/shell split + tier rendering, T13.3 shared includes, T13.4 fable-mode discipline into MICRO_LOOP, T13.5 gate).

**Date:** 2026-07-06 · **Ticket:** T13.1 (module M13, lane `prompt`) · **Program:** [bpm-agent-amplifier EXECUTION_TICKETS.md](../../../bpm-agent-amplifier/docs/sdlc/EXECUTION_TICKETS.md)

## 0. Scope & methodology

**The exact audit question applied** (verbatim, from field research on frontier-model instruction audits — see `bpm-agent-amplifier/docs/research/FABLE5_FIELD_REPORTS.md` §2):

> "Read your instruction files end-to-end. Where do they contradict? Which rules manage weaker-model failures you've outgrown? What teaches by bad example? Don't fix — report first."

**Classification scheme**, applied at the instruction-block level (not just per-file):

- **Constraints** — real guardrails necessary regardless of model capability (safety, scope boundaries, correctness invariants, non-negotiable process). Keep.
- **Calibration** — directionally right but containing stale/wrong values (dates, model names, versions, thresholds, file/rule counts). Needs updating, not removal.
- **Scaffolding** — verbose or over-specified instruction that exists to compensate for a *weaker* model's judgment. Candidate for condensing/tiering on the frontier path — but this repo's agents run on BOTH frontier and local models (qwen3.6, gemma-QAT), so scaffolding is flagged, not deleted outright.

**Scope:** every file under `agents/**` (115 `.md` files, ~154k words) and `skills/**` (38 `SKILL.md` wrapper files, ~10k words) in this repo — the canonical source for both the opencode install and the generated `attest-claude` Claude Code build. Audited in 7 independent parallel passes (batches A–G below), each a full read-end-to-end by a frontier-tier (Fable) model, per the ticket's "run on best available model" instruction.

**Headline meta-finding:** the system's contradictions are concentrated almost entirely in the *older, larger* files — the SDLC orchestrator modes (`sdlc-init-*`, `sdlc-improve-mode`, `sdlc-feature-mode`), the `agents/shared/` protocol layer, and the oldest specialist agents (`code-reviewer.md`, `performance-engineer.md`, `ux-engineer.md`). The *newer*, single-purpose agents (`a11y-compliance`, `cost-engineer`, `reliability-engineer`, `data-steward`, `analytics-architect`, `llm-integration-engineer`, `challenger`, `task-decomposer`, `release-manager`, `dead-code-detector`) are lean, internally consistent, and nearly contradiction-free — hard rules + input contract + gate, almost no drift. `agents/shared/MODEL_ADAPTER.md` is the one file that already implements genuine tier-conditional instruction (explicit per-tier tables, e.g. "large tier: skip LOCAL_LLM_PRIMER — not needed"). Both are useful templates for T13.2's restructure. Nearly every contradiction found traces to **copy-paste boilerplate drift** across many files rather than deliberate disagreement — the shared blocks (Loop Prevention, Context Budget, Research Tools, Completion Manifest, Progress Announcements, Bounded Task Mode, Persistence) are pasted verbatim into ~40+ files instead of referenced from one source, and each paste has quietly diverged.

## 1. Systemic cross-cutting findings (ranked by blast radius)

These recur across multiple batches / affect the whole system, not a single file.

### 1.1 HANDOFF delimiter self-contradiction — highest blast radius
`agents/shared/HANDOFF_TEMPLATES.md` mandates: "Every HANDOFF block MUST use the standard delimiter format" (`════` lines), and `SESSION_PRIMER.md`/`LOCAL_LLM_PRIMER.md` reinforce "do not use `---` or any other separator." Yet **Templates 2–10 in that same file all use `---` banners** — only Template 1 and `HANDOFF_QUICK_REF.md` comply. Template 10 additionally drops the `SDLC-TASK for` trigger prefix that Bounded Task Mode keys on, so pasting it verbatim produces a specialist that never enters bounded mode. Every SDLC mode file (`sdlc-init-phases-0-2.md`, `sdlc-init-phase-5.md` — which uses banned `─` box-drawing — `sdlc-onboard-mode.md`, `architecture-designer.md`, `code-reviewer.md`, `security-auditor.md`) models one of at least three different HANDOFF dialects (full `════`, `---`, or a loose `HANDOFF to:` key-value form). Per project memory, the discipline validator only checks `task()` call sites, not `HANDOFF to:` format — so this is exactly the validator blind spot that let a prior gap (security-auditor's missing gate) slip through, and it is the single most-copied bad example in the corpus.

### 1.2 Executor-selection story is stale in ~6 files
`agents/shared/EXECUTOR_SELECTION.md` is the current truth (Executors A/B/C/D, A→B→C preference order, "C is an error under `autonomy: auto`"). But: `SESSION_PRIMER.md` Rule 3 and `LOCAL_LLM_PRIMER.md` Rule 3 are both *titled* "No task() calls" while their bodies say the opposite (a heading fossil from before issue #20059 closed); `FIX_VERIFY_LOOP.md` still says "User opens N concurrent OpenCode sessions"; `GATE_SCORING_PROTOCOL.md` Step 4 says "ask user to re-run the agent"; every `HANDOFF_TEMPLATES.md` template header says "Open a new OpenCode conversation and paste this EXACT prompt"; `agents/sdlc/PARALLEL_WAVE_PROTOCOL.md`'s Round 1 template hardcodes "open 3 OpenCode sessions" with no `has_task_tool` gate at all; and `skills/review/SKILL.md` flatly states "`task()` does not work in OpenCode" as if universal. Only `agents/sdlc/onboard/health-coordinator.md` (checks `docs/work/.model-context` for `has_task_tool`), the `reflow` skill, and `PHASE_ROUTING_PROTOCOL.md` were updated to the current executor-selection model.

### 1.3 Loop-prevention / tool-call-cap incoherence
Three competing philosophies coexist. `LOOP_PREVENTION.md` Class 3 explicitly *repudiates* numeric caps: "Arbitrary total-call limits are therefore unnecessary and hurt quality by forcing early exit... stop based on what you know, not how many calls you've made." Yet `agents/shared/blocks/loop-prevention.md` **and** its `.compact.md` sibling — both citing that same canonical file as "Full rules" — assert "success loop → hard cap 15 total calls / 4 per work-unit." Individual agents add their own numbers on top: `sdlc-init-mode.md` and `sdlc-onboard-mode.md` each carry **both** "hard cap: 30 tool calls" and "success loop → 15 total calls max" *in the same file*; `sdlc-lead.md` uses a 2-strike schema cap where every specialist uses 3; `researcher.md`'s own philosophy ("this removes the need for arbitrary call limits") sits next to its own numeric ceilings ("pass ≤ 4," "2-4 passes, 3-6 sources"). Several caps are **arithmetically impossible** given the agent's own mandated procedure: `static-perf-analyzer.md` (15 calls vs. 5 mandatory scans + confidence re-passes), `anti-slop-auditor.md` (20 calls vs. 28 rules + LDR-on-5-files), `playtest-evaluator.md` (15 calls vs. 3 sessions × ≥5 plays or 15 minutes each via browser automation), `game-balance-designer.md` (15 calls vs. simulate→tune×3→report), `health-coordinator.md` (15 calls vs. read 2 inputs + write manifest + write USE_CASES + read up to 7 review files + write assessment), `test-engineer.md` and `git-expert.md` (small caps vs. per-operation before/after verification workloads).

### 1.4 Confidence / severity scale mismatches
Pass threshold "≥7 on a 1-10 scale, <5 = automatic fail" is the system-wide convention — except `code-reviewer.md`, which requires "confidence score ≥75" (a 0-100 scale) while its own Phase Mode elsewhere uses 1-10. `LOOP_PREVENTION.md` Class 3 says "Confidence ≥ 8 → mark DONE" for research units vs. `GATE_SCORING_PROTOCOL.md`'s ≥7. Severity derivation itself has forked three ways: CVSS-informed CRITICAL/HIGH/MEDIUM/LOW (`FINDING_SCHEMA.md` and most security/code-review/perf agents), DREAD 1-10 averaging (`OWASP_METHODOLOGY.md`'s threat-modeling phase, which `threat-modeler.md` then re-flattens back to CRITICAL/HIGH/MEDIUM/LOW), and ad hoc CRITICAL grants to *unmeasured static* findings that the shared schemas reserve for measured, user-felt impact (`concurrency-checker.md`, `db-query-analyzer.md`, `bundle-analyzer.md` all grant CRITICAL where their own `performance/FINDINGS_SCHEMA.md` would say HIGH at most; `complexity-analyzer.md`'s CC-thresholds are a full severity level higher than `code-review/FINDINGS_SCHEMA.md`'s table for the same metric).

### 1.5 A stale factual claim is used as a merge-blocking rule
"V8 cannot apply JIT optimizations to any function containing try/catch — 5-20x slowdown" appears in `agents/performance/METHODOLOGY.md`, `static-perf-analyzer.md`, and is enforced as merge-blocking rule R-02 in `agents/code-review/error-handling-auditor.md`. Modern V8 (TurboFan) has optimized try/catch since roughly Node 8 (~2017) — this is outdated engine folklore driving CRITICAL severity across two specialist clusters that also dispute *ownership* of the same underlying code pattern (perf METHODOLOGY explicitly calls try/catch-in-loop "DISTINCT from correctness issues, which the code-reviewer owns," while error-handling-auditor blocks merges on exactly that pattern under R-02/R-04). This is the clearest literal instance of "a rule that manages a failure you've outgrown" the audit prompt asks about — except the outgrown failure belongs to a *JS engine*, not a model.

### 1.6 A dead file that isn't actually dead, and has drifted ahead of its replacement
`agents/sdlc-init-phases-3-4.md` carries a header saying "do not load... retained only because three docs still reference the old name — update those references, then delete this file," but its own body 15 lines later says "Load only when sdlc-init-mode.md directs you here," and it still ships the full executable Persistence banner ("never end your turn after announcing an action"). Worse: **it has drifted ahead of its live replacement.** Its code-review handoff lists the current 9-dimension review including "tech-stack compliance" (the v1.27.1 addition), while the live `sdlc-init-phase-4.md:655` still claims "9-dimension" but lists only 8 items, missing tech-stack compliance entirely. Someone updated the deprecated copy instead of (or in addition to) the live one — direct evidence the historical phases-3-4 duplication is an active source of drift, not just a tombstone.

### 1.7 A promised phase that was never delivered
`sdlc-init-phase-4.md`'s frontmatter, header, and load-note all say "Phase 4 & Phase 5 (Release)" — but the file ends at Phase 4's exit criteria with no Release section at all. An orchestrator directed here for Phase 5 finds nothing.

### 1.8 Stale reference-counts cited as load-bearing facts, system-wide
- `BOUNDED_TASK_CONTRACT.md` header: "Six canonical rules" — the file has **ten** (Rules 7-10 were appended without updating the header or any of the ~5 downstream files that cite "the six rules").
- `SESSION_PRIMER.md` header: "six core rules" — the file has **seven** (Rule 7, memory, was added later).
- `EXECUTOR_SELECTION.md` heading: "The three executors" over a **four**-row table (A/B/C/D — D was formalized per v1.26.4 without fixing the count).
- `ANTI_SLOP_RULES.md` is cited elsewhere (`agents/code-review/METHODOLOGY.md`) as "20 rules (R-01 through R-20)" — the file actually defines **28** rules, and the code-reviewer's own dimension-count arithmetic (7/8/9) is inconsistent within a single file across its header, tracker, Phase 3, Phase 5, and Phase 6 sections.
- `OWASP_METHODOLOGY.md` contradicts *itself* on its own custom-rule inventory: "98 gap-filler rules across 5 languages" (line 74) vs. "186 rules across 11 languages" (line 124) — same artifact, two numbers, in the same file.
- OWASP edition label stuck on "Web Top 10 (2021)" (`owasp-web-checker.md`, `OWASP_METHODOLOGY.md`, `agents/templates/OWASP_TRACKER_template.md`) while `owasp-llm-checker.md` is already on "LLM Top 10 (2025)" — inconsistent vintages within one security family, and the underlying taxonomy is due for the 2025 web revision.
- `skills/review-code/SKILL.md` usage line says "8-dimension" while its own body says "9 dimensions" two lines later.

### 1.9 Tool/service naming trichotomies that will fail strict-schema local models
- Web search tool spelled `web_search` / `WebSearch` / `websearch` across sibling agent files (sre-engineer, db-architect, container-ops, api-designer use `WebSearch`; git-expert uses `websearch`; the canonical registered name elsewhere is `web_search`).
- Memory MCP namespaced three different ways: `mcp__memory__*`/`memory__*` (`MEMORY_PRIMER.md`), `mempalace_*` or `bpm-memory-mcp_*` (`RESEARCH_TOOLS.md`), and "mempalace" (`MODEL_ADAPTER.md`).
- Orchestrator state file named both `docs/work/STATE.md` (`CHECKPOINT_STATE.md`'s "single source of 'where am I'" claim, `skills/sdlc`'s `/sdlc resume` description) and `docs/work/sdlc-state.md` (`HANDOFF_QUICK_REF.md`'s mandatory pre-HANDOFF write, `GATE_SCORING_PROTOCOL.md` Step 1, both primers' quick-refs, `skills/gate`, `agents/sdlc/PARALLEL_WAVE_PROTOCOL.md`) — two files, each claimed as *the* single source of truth by different protocol documents.

### 1.10 The compact/full shared-block split has rotted toward the stale side
`agents/shared/blocks/*.compact.md` files are hand-frozen snapshots that now actively disagree with the canonical files they claim to summarize:
- `loop-prevention{,.compact}.md` teach the deleted "15 total / 4 per work-unit" cap that `LOOP_PREVENTION.md` Class 3 explicitly repudiates.
- `context-budget{,.compact}.md` assert a "max 4 files (small tier) / max 8 (medium)" rule that **appears nowhere** in `CONTEXT_BUDGET.md`, the file they cite as "Full rules."
- `research-tools{,.compact}.md` teach `web_research()` as the primary/first-choice call; `RESEARCH_TOOLS.md` demotes `web_research` to "tier 3 — escalate only" and mandates "always start at tier 1, `web_search_pullmd`" — the blocks describe a pre-pullmd tool surface that no longer matches the full guide, and omit pullmd entirely.

This is directly relevant to T13.2: the compact/full split **is** basically the tier-inverse pattern the ticket wants — but right now the compacts are stale hand-copies, not derived artifacts, so any restructure needs a regeneration step or the drift recurs immediately.

### 1.11 Security/correctness guardrails at risk of being misclassified as scaffolding
Several rules read like weaker-model hand-holding but are load-bearing and must survive any frontier-tier condensation: "BLOCKED … never improvise inputs" (repeated verbatim across nearly every specialist's input contract); "never `|| true` a scan command — a silent error is a false clean" (`OWASP_METHODOLOGY.md`, `semgrep-runner.md`); the secrets-scanner's mask-and-gitignore steps (protects against the scanner leaking the plaintext secrets it just found); the zero-results guard ("0 findings ⇒ investigate, don't report clean"); and `coding-agent.md`'s own Law 2 ("mark BLOCKED and stop — do not write an unverified external API from training data... the default must protect the weak one"), which is notably the **one** place in the whole corpus that explicitly self-labels its own tiering intent. T13.2 should carry all of these forward as Constraints, not condense them away.

### 1.12 A literally corrupted protocol file
`agents/shared/LOOP_PREVENTION.md` lines ~108-111 contain an orphaned template fragment — a dangling `- Workaround attempt: <if any>` bullet, a stray closing code fence, and floating "Recommend: ask the user to either (a)…" text — clear remnants of an incomplete edit. This sits inside the one file every agent is instructed to read at the start of any task, and (fittingly, given the file's subject) is itself a case of malformed structure nobody caught.

### 1.13 Concrete broken commands and examples, taught as canonical
These are copy-and-it-breaks risks with real operational consequences, found across multiple batches:
- **`sdlc-lead.md`'s tracker-archive one-liner** (`mv SDLC_TRACKER.md ARCHIVE && head -20 ARCHIVE > SDLC_TRACKER.md`) keeps the **oldest** 20 lines via `head`, while the stated intent is "keep current phase + last-completed phase" (the newest rows, which need `tail`). Run verbatim, it destroys the recent tracker state it claims to preserve.
- **`container-ops.md`'s flagship multi-stage Dockerfile** copies `node_modules` built via `npm ci` (which installs devDependencies) straight into the production stage — directly contradicting the file's own `npm ci --omit=dev` optimization rule two sections later. It is the single most-likely-to-be-copied code block in the file.
- **`agents/security/IaC_METHODOLOGY.md`** states "Never silence errors with `|| true`" and then its own Phase 1 sample commands (checkov, trivy) append `|| true` two lines later — inherited verbatim by `iac-security-checker.md`.
- **`agents/performance/bundle-analyzer.md`**'s "20 largest images" pipeline (`ls -la | sort -rn | head -20`) sorts by the permissions column, not file size — it doesn't do what its own comment claims.
- **`agents/migration-planner.md`**'s Step 4 output template nests a ` ```sql ` fence inside a ` ```markdown ` fence — the inner fence closes the outer block early, so the template renders broken the moment it's copied as written.
- **`agents/test/E2E_INFRASTRUCTURE.md`**'s canonical `BasePage.waitForLoad()` uses Playwright's own explicitly-**discouraged** `waitForLoadState('networkidle')`; separately, its CI workflow never sets the `TEST_DATABASE_URL` env var that `global-setup.ts` reads (`process.env.TEST_DATABASE_URL!`), so the non-null assertion silently produces the literal string `"undefined"` as a DB URL, compounded by an invalid `sqlite:` Prisma URL scheme (should be `file:`).
- **`sdlc-init-phase-5.md`**'s Round 3 audit fan-out drifts between "3 parallel HANDOFFs" (header) and "4" (body, adding a doc-gaps audit) — the 4th is then silently absent from the Round 4 release gate and from `validate-release-readiness.sh`'s 10 listed conditions, meaning a release can ship without the very doc-gap audit the file says it waited for.
- **`agents/security/OWASP_LLM_METHODOLOGY.md`** shows VULNERABLE code blocks with no adjacent SAFER contrast for five of ten LLM categories (LLM04, 07, 08, 09, 10) — a weak model pattern-matching on the example has only the anti-pattern to imitate for those five.
- **`agents/sdlc/onboard/component-mapper.md`**'s "circular dependency" check (`grep -rn "from.*\.\." src/`) matches any parent-relative import — i.e., normal code — and detects zero actual cycles.
- **`agents/performance/concurrency-checker.md`**'s detection greps (`grep -rn "def async\|async def"`, unbounded `let \w* =|var \w* =` for "race conditions") are near-zero-precision nets that flag almost every mutable variable or, in the Python case, half-match invalid syntax.

### 1.14 Path-root duality
`~/.config/opencode/agents/shared/...` (opencode-install-absolute) and `agents/shared/...` (repo-relative) are used interchangeably — sometimes within the *same file* (`test-engineer.md` line 197 vs. 340; `coding-agent.md` line 18 vs. 221) — across the majority of files in the corpus. Since this repo is the canonical source for both the opencode install and the generated `attest-claude` Claude Code build, one of the two forms is wrong in any given runtime; a weak model will read-fail on the wrong one and, per its own loop rules, may burn retry strikes doing so. `ui-verifier.md` additionally references `~/.claude/agents/shared/BROWSER_TESTING.md` — the only `~/.claude/` (generated-repo) path found anywhere in the canonical repo, backwards relative to the dual-repo build direction.

### 1.15 Review-shaped skill-name collision
`skills/review-code` and `skills/review` are genuinely distinct in substance (single-agent code-health audit vs. a 3-expert multi-pass coordinator that itself routes into `/review-code`), but the disambiguation lives only on `review-code`'s side ("Distinct from `/review`"); `review/SKILL.md` never states when to prefer the other. Combined with Claude Code's own built-in PR-review command, there are effectively three or four review-shaped entry points a user could reach for. `skills/review/SKILL.md` also still hardcodes the pre-`EXECUTOR_SELECTION` assumption ("`task()` does not work in OpenCode... user opens 3 concurrent sessions"), making it one of the most stale files in the skills layer despite being one of the most likely to be invoked.

## 2. Per-batch detailed findings

The following sections are the seven parallel audit passes in full, each covering a distinct slice of the corpus. This is a per-file analysis conducted through the Constraints/Calibration/Scaffolding/Contradictions-or-bad-example-teaching lens defined in §0 — not a literal tag stamped on every individual instruction line, but a structured pass over each file that surfaces what falls into each bucket, followed by that batch's own cross-file section.

### Batch A — SDLC init/improve/feature modes + researcher (6 files)
`agents/sdlc-init-phases-3-4.md` (deprecated) · `agents/sdlc-init-phase-3.md` · `agents/sdlc-init-phase-4.md` · `agents/sdlc-improve-mode.md` · `agents/sdlc-feature-mode.md` · `agents/researcher.md`

Confidence-below-5 behavior conflicts with Bounded Task Mode's "stop means stop, do not ask for follow-up" when researcher is invoked as a bounded specialist.

### Batch B — Core specialist agents (9 files)
`test-engineer.md` · `sdlc-lead.md` · `git-expert.md` · `sre-engineer.md` · `db-architect.md` · `frontend-design.md` · `coding-agent.md` · `container-ops.md` · `api-designer.md`
